# 系统提示词编辑器实施与验收计划

状态：实现完成，候选待 review；执行覆盖与限制见第 8 节。更新日期：2026-11-04。

产品规则以[系统提示词编辑器设计](../spec/system-prompt-editor.md)为准；保持[原系统提示词设置](../spec/system-prompt-settings.md)的 schema、保存和会话快照合同。本文只登记实施依赖和验收，不把既有 SP 测试结果记作新增功能通过。

## 1. 目标与采用的规则

| 项目                                         | 状态与来源                                 |
| -------------------------------------------- | ------------------------------------------ |
| 当前草稿完整效果、会话实际内容，两种分开显示 | 用户明确选择两种都要                       |
| 动态上下文展开内容；解释章节操作和模拟条件   | 用户提出的页面缺口                         |
| 全局 Profile、章节模板、自定义章节           | 用户提出的设计方向；正文和收藏范围见 D02   |
| 文本 diff；红删绿增，帮助理解变化            | 用户明确要求                               |
| 唯一设置保存链、创建期快照、并发保护         | 保持现有合同                               |
| Profile 无库、应用不自动保存、允许整体替换   | 本计划沿用此前推荐方案；整体后果必须可预览 |

用户授权按本计划实施，D01–D03 采用表中推荐方案。内置章节模板首批提供沟通章的简洁／解释、执行章的验证清单，均只追加规则。

| ID  | 规则问题                                   | 采用方案                                                      | 其他选择与影响                                                   | 影响切片                 |
| --- | ------------------------------------------ | ------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------ |
| D01 | 应用后仍有未点名的无效草稿，是否允许应用？ | 完整候选校验失败则整体拒绝并保留原稿；脏但合法可应用          | 允许无效候选需另定义应用与保存两层校验规则                       | P4；PP05 的无效草稿分支  |
| D02 | 章节模板第一批内容，以及是否保存个人模板   | 内置沟通简洁／解释、执行验证清单模板；个人收藏另立范围        | 个人收藏需要持久化、命名、删除及多端归属；不能直接放入浏览器缓存 | P4；SPE13                |
| D03 | 实际请求内容保留多久、多少份？             | 每个常驻交互式主会话仅最近一份，随 runtime 回收；无历史正文库 | 保留历史／重启恢复需要额外存储、容量及生命周期设计               | P0、P2；SPE06 的回收分支 |

合同已冻结：Profile 2 MiB，id/name 80 字符、description 1000 字符；预览文档 1 MiB／1024 块；每 runtime 最近一个 requestId。只读方法为 systemPrompt/preview 与 session/systemPrompt，具体字段见产品 spec。

## 3. 状态维度与剪枝

| 维度     | 代表值                                                      | 重点组合                                           |
| -------- | ----------------------------------------------------------- | -------------------------------------------------- |
| 草稿     | 干净、脏合法、脏无效、外部冲突、保存中                      | 模板应用／预览返回／保存失败                       |
| 编辑方式 | sections、replace，双向切换                                 | 未点名章的生效变化、隐藏 replacement、自定义章暂停 |
| 章节     | 规则、混合、generated、自定义                               | 追加／替换／关闭、重复 id、条件缺席                |
| 预览来源 | 合成环境、固定上下文、真实请求；缺失／过期／截断            | 原文与反事实区分，diff 不把缺失当空文              |
| 目标     | 本机／远程，A→B；同路径不同 identity／runtime 代次          | 迟到响应和重连隔离                                 |
| 客户端   | Desktop continuous、手机 replayable；宽／窄、中／英、浅／深 | 查询重取、完整阅读、红绿及辅助符号                 |
| 文件     | UTF-8、多字节跨片、语法错误、超限、用户取消                 | 完整读取、原子拒绝、粘贴与文件同 schema            |

剪枝：不做所有 provider／模型的全排列，用代表性请求布局和合成 fixture 验证捕获边界；权限、queue、compact／goal 不新增产品动作，只检查预览无副作用。正文历史归档、个人模板库和模型／项目级 Profile 为范围外候选。

## 6. 验证与 E2E 交接

实现前使用 architecture-governance 的 changed 检查和目标模块受控上下文。基线已更新到 v3.17.1 主线：App 业务单测链已退役，不新增 App test/spec 或 contract.test.ts；App 行为使用浏览器验收、可重复运行时场景和 E2E，CLI 先补定向回归测试。

实现阶段必须执行 `pnpm typecheck`、`pnpm lint`、改动文件格式检查和 `pnpm architecture:check --changed`。提交／推送前运行 `pnpm verify:pre-push`。保留真实失败及范围；不调用用户未要求的全量 pnpm test／test:unit。

验证分层：

- CLI 集成回归：消费 shared schema／合并，验证上限、顺序、逐字保留、导出与实际组装。
- 浏览器验收：dirty／baseline／冲突、候选过期、来源标签、错误、模板和窄屏入口。
- CLI／协议定向测试：同输入 builder 一致、实际请求采集来源、无副作用、目标与代次路由、完整性。
- 浏览器／Desktop 候选：完整编辑路径、红绿 diff、展开、搜索、复制、保存／重进，截图检查深浅主题、中英和手机宽度。
- 会话实际内容候选：本地合成 provider 捕获请求；与展示正文逐字核对，并断言打开预览后请求计数未增加。使用受控时序，不以固定 sleep 判断稳定。
- 真实手机 attachment、远端 Host／重连、Windows／Linux 原生文件对话框分别登记证据；桌面窄屏不充当手机链路验收。

仅编辑／模板／合成预览的 E2E 不发送模型请求；实际请求观测用隔离、无真实凭据的 case-local synthetic provider。测试文件与 HOME／数据目录隔离，使用合成 AGENTS、Git、技能和记忆资料。

E2E 保持 `manual-review/pending` 候选。人工 review 后按现有流程决定转正／Docker 准入。已有 SP01–SP15 是回归基线，不能替代本表新增证据。
