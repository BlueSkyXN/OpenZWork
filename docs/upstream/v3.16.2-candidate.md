# OpenZWork v3.16.2 候选版本说明

本候选从 OpenZWork v3.16.1 主线继续，整合 ZCode v3.16.2（`3c5b227649371507ddc4eb46ac5133afe6db1cab`），并包含本仓维护修复与 Bot 回归补强。源码整合、维护修复和测试维护分别见 [PR #30](https://github.com/BlueSkyXN/OpenZWork/pull/30)、[PR #31](https://github.com/BlueSkyXN/OpenZWork/pull/31)、[PR #32](https://github.com/BlueSkyXN/OpenZWork/pull/32)。正式发行版本以 [OpenZWork Releases](https://github.com/BlueSkyXN/OpenZWork/releases) 为准。

## 升级内容

- 吸收侧栏完整会话视图、会话 tab、主区域布局和未读徽标修正；保留按 workspaceIdentity 与 remoteSessionId 隔离的订阅及恢复语义。
- 修正旧工作区首次迁移后的本地/远程顺序。同库 Desktop 与 Source Server 启动可幂等补齐各自 Host 行，保留已有任务归属与 CLI 会话事实。
- 吸收工作流并发调度、子进程输出完成、流式呈现、插件目录及远端探测/部署修正。
- node_repl 宿主 seed 与仓内 0.6.1 manifest 对齐；补齐既有默认清单中 `skill-creator`、`plugin-creator`、`zcode-guide`、`visualize` 的本地注册。用户已保存的启停和卸载抑制选择继续优先。

完整规则与迁移验收见 [v3.16.2 整合规范](../spec/upstream-v3.16.2-integration.md)。

## 维护修复

| 登记    | 触发场景                                                       | 候选行为                                                               |
| ------- | -------------------------------------------------------------- | ---------------------------------------------------------------------- |
| OW-P001 | 设置页选择远端 Source 的用户级 MCP，目标没有 workspaceIdentity | 读写所选 Source 的目录服务；重连更新服务引用，服务缺失时报告失败       |
| OW-P002 | Web token 含 `+`、`/`、`=` 等字符，首次 URL 访问后使用 Cookie  | Cookie 在比较前只解码一次；有效 token 可继续访问，错误或畸形编码仍拒绝 |
| OW-P003 | PRV-08 用例清理时，Registry 后台刷新仍持有文件锁               | 测试夹具等待既有刷新队列完成后释放资源，消除该清理竞态                 |
| OW-P004 | Windows affected 测试入口收到显式路径或 manifest               | 使用真实路径和统一分隔符匹配 Vitest 依赖图，正确选择相关测试           |
| OW-P005 | MCP 新增、修改、启停或删除写入失败                             | 返回失败并保留原界面投影；写入成功后才执行完成动作                     |
| OW-P006 | MCP 保存期间切换 Source、切回原 Source 或发生重连              | 结果回写核对目标与服务代次，丢弃过期结果，保护当前 Source 配置         |
| OW-P007 | 消息流测试中的立即成功 HTTP 替身被后台轮询消费                 | 测试工厂隔离后台任务、等待异步清理并检查无意外轮询；生产轮询不变       |

每项的来源、根因证据、回归及退役条件见[下游补丁清单](downstream-patches.yaml)。Bot 维护另外补充 Feishu runtime 锁交接、attached remote 后台隔离、自动化成功/失败投递和绑定状态下的错误 UI 覆盖，并将相关回归纳入固定核心 CI。当前执行层级见 [Bots 覆盖矩阵](../testing/bots-e2e-coverage-matrix.md)；CF-01 保持 `manual-review/pending`。

## 产品与数据边界

- 用户级目录沿用 `.openzwork`；项目 `.zcode`、通用 `.agents` 和既有 CLI 命令约定保持。独立的数据目录兼容开发未纳入本候选。
- 模型配置继续使用本地 Built-in 文件、16 个第三方模板及 Personal 配置；官方账号、商业权益、CDN 配置同步、云端分享/反馈、产品遥测、原生 CUA 和官方自动更新保持移除。
- 标准 MCP 与 MCP OAuth、第三方 Bots、Browser Use 页内控制、本地自动化与工作流、远程工作区和无账号 HMAC 配对继续保留。
- 本地 App Usage、日志导出、资源窗口及 ModelIO 诊断各自沿既有所有者维护；入口与边界见[本地诊断职责](../electron/resource-manager.md#本地诊断职责)。

## 验收与更新

候选验收要求同一提交的三平台核心 CI、七组完整 Extended、Desktop Main/E2E 类型审计和 Installers 通过。精确 SHA、运行编号与失败重试情况记录在 PR 检查和交付记录中；前一层 PR 的安装包不替代最终候选验收。

此前 Extended 和本地核心检查出现过 services worker OOM。收尾诊断复现了消息流夹具的无界空轮询，按 OW-P007 修正测试隔离；历史失败没有堆快照，不能据此逐次确认同一根因。最终候选需完整通过既有核心与 Extended 配置。

默认 Installers 构建产生 Preview 候选。正式安装包与 Preview 使用不同身份；正式版本发布后，从本仓 Releases 下载对应平台安装包手动更新。构建、tag 与发布步骤见[构建与发布流程](../git/release-build-publish-separation.md)。人工试装、真实租户、手机 UAT 及 pending E2E 转正单独记录。
