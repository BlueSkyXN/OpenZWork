# 自定义命令改名与保存失败

## 规则与所有者

`ICommandsService.updateCommandFile` 负责设置页编辑命令时的文件更新；接口、作用域选择和 HOME 隔离规则保持不变。`commandsService` 是该操作中文件与禁用状态的唯一写入者，UI 等待返回结果后刷新列表。

- 目标名称已被另一个文件或目录占用时，返回重名错误，原命令、目标内容和禁用配置均保持原样。
- 改名或移动作用域时，先生成并成功写入新文件，再删除旧文件。目标目录创建或写入失败时保留旧命令。
- 不同文件路径的写入使用排他创建，避免检查名称之后的并发保存覆盖目标；竞争失败的一方保留原命令。
- 原路径编辑仍更新同一文件。大小写敏感文件系统按普通改名处理；不敏感文件系统上仅改变名称大小写时，识别同一个普通文件并保留该改名能力。
- 正常改名保留未知 frontmatter 字段，并把原路径的禁用状态迁移到新路径。旧文件清理只忽略 ENOENT，其他失败向调用方报告。

```text
设置页保存 → CommandsService（唯一写入者）
  → 校验目标作用域、读取原命令
  → 生成内容、确认是否为同一文件的路径别名
  → 保存新文件（不同文件排他创建；失败保留原命令）
  → 删除旧文件 / 更新文件名大小写
  → 沿用现有禁用状态迁移 → 返回命令 → UI 刷新
```

本修复限定为命令文件保存顺序，不新增持久化格式、状态副本或依赖。文件与 CLI 配置仍分别保存；不引入跨文件事务，也不改变同一路径编辑的写入方式。

## 验收

在临时 HOME 与项目目录调用真实服务，验证：

1. A 改为已存在的 B 失败，A/B 内容和配置不变。
2. 目标父目录无效、目标文件名超过文件系统限制时，失败后旧文件仍完整。
3. 正常改名后的内容、未知 frontmatter、禁用状态和列表一致，旧路径移除。
4. 原路径编辑与仅改变大小写的改名成功。
5. 两个命令同时改为同一目标，仅一个成功，失败方原文件保留，目标内容属于成功方。
